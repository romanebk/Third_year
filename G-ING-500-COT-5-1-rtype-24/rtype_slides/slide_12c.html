The Registry
Everything a system, a script or the editor can ask it.
EntitiesCRUD
Ccreate("Bug", {"enemy"})a new id + its card
Cinstantiate("prefabs/bug.yaml")from a prefab, children included
Cclone(e)same components, new uuid
Ralive(e) · info(e)still valid? name, tags, parent
Urename · tag · untagedit the card
Ddestroy(e)children too · at the end of the frame
ComponentsCRUD
Cadd<Velocity>(e, …)attach data to an entity
Rget<Health>(e)must exist
Rtry_get<Health>(e)maybe: returns nothing if absent
Rhas<Weapon>(e)yes or no
Ureplace<Sprite>(e, …)swap the value · fires "changed"
Dremove<Poisoned>(e)the effect wore off
Find & queryREAD
find(uuid) · find("Boss")one entity, by uuid or by name
view<Transform, Velocity>()every entity with both: a system's loop
with_tag("enemy")every entity with the tag
with_tags({"enemy", "flying"})all of them at once
parent(e) · children(e)walk the tree
set_parent(child, parent)the Force docks on the ship
ScenesMANAGER
load("level_1.yaml")two-pass loader: create, then link
switch_to("boss")unload the old one, load the new
persist(e)survives the switch: the player
unload() · active()free it · which one is running
save("save_1.yaml")uuids and components back to a file
on_create · on_destroycallbacks: sounds, network, editor
Stores and finds, never decides. The registry has no game logic: systems ask it, then act. The same API serves the game, the scripts and the editor.
Destroying inside a loop breaks the loop you are in. Mark it, destroy at the end of the frame: same trap as the vector realloc.
