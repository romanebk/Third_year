Scripting
Behaviour in a script, not in C++. Change it, save it: no recompile.
scripts/bug.lua a designer writes this
saved · hot reload
local amplitude = 60
local speed = 120
local fire_every = 2.0
function on_spawn(self)
self.t = 0
end
function on_update(self, dt)
self.t = self.t + dt
self:move(-speed * dt,
math.cos(self.t * 3) * amplitude * dt)
if self:every(fire_every) then self:shoot("aimed") end
end
function on_death(self)
spawn("powerup", self.x, self.y)
end

How it works engine side
The engine calls hooks: on_spawn, on_update, on_hit, on_death.
The script only sees what you expose: move, shoot, spawn, player_pos… No files, no sockets: a sandbox.
Hot reload: watch the file, reload it when it changes. Designers tune while playing.
A Script component names the file. The prefab stays data, the behaviour becomes data too.
Scripts run in the room. Gameplay decides there, like the rest: clients never run gameplay scripts, at most cosmetic ones.
Lua is the classic choice: small, fast, made to be embedded. Its C API, or a binding like sol2. Look at how Roblox (Luau) or WoW add-ons use it.
