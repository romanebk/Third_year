Modding
Let players change your game, without your source code. Learn from Minecraft.
Resource packs how it looks
# a folder (or a zip) dropped in packs/
retro_red/
├─ pack.yaml name, version, priority
└─ assets/rtype/
├─ sprites/player.png ← same path
├─ sounds/shot.ogg as the game's:
└─ lang/fr.yaml it wins
Override by path. The engine looks for a file in every enabled pack, top priority first, then in the base game. Textures, sounds, texts: no code.
Data packs & tags how it plays
# data/rtype/tags/enemy/bosses.yaml
replace: false # merge with the others
values:
- rtype:dobkeratops
- bydo_plus:giga_crab # a mod adds itself
- #bydo_plus:minibosses # tags nest
# level_3.yaml asks for the tag, not a list:
boss: { pick: "#rtype:bosses" }
Tags are named groups. The game logic asks for the group, so a mod joins it and just works. Namespaces (rtype:, bydo_plus:) avoid collisions.

For code: plugins (.so / .dll) and Lua scripts. Minecraft's mod loaders (Forge, Fabric) do the same for Java.
For R-Type: everything a designer adds (sprites, sounds, enemies, levels, tags) already lives in files. A modder is just a designer from outside your team.
Look it up: how Minecraft resource packs, data packs and tags work, and how Factorio or Skyrim load mods. Then document your format: modders need a how-to.
