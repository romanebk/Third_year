Dynamic or Static?
How the core finds its plugins, components and systems. Your call — pick early.
Dynamic.so / .dll
// loaded at runtime — remember Arcade
void* h = dlopen("plugins/graphics_sfml.so", RTLD_NOW);
auto make = (IGraphics*(*)())dlsym(h, "entry_point");
IGraphics* gfx = make();
  • Easy to use: drop a file, it's loaded
  • Swap SFML ↔ raylib without recompiling
  • Each .so is standalone: its own target, its own deps
  • Build gets complicated: exports, paths, LoadLibrary on Windows
Static.a + factory
struct Position { float x, y; };
REGISTER_COMPONENT(Position) // macro
// tools/gen_registry → components.gen.hpp
// lists every REGISTER_* found → the factory
  • One binary, simple build, compiler checks everything
  • New component = one macro, the script adds it
  • Recompile to add or swap anything
  • A codegen step to write and maintain
Either is fine. Justify it in your comparative study — with a benchmark if you can.
